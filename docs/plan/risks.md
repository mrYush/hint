# Cross-cutting risks and mitigations

| # | Risk | Phases affected | Mitigation |
|---|---|---|---|
| R1 | **Parser, index-backend and native-helper dependencies** break cross-compilation, mobile embedding or device resource budgets | 2, 5 | The core must always build without cgo. Evaluate parser and storage-driver/runtime choices before selection, including pure-Go SQLite/FTS5, Bleve or a Tantivy helper; verify all six release targets and mobile build/runtime separately, including WASM/process restrictions, cancellation and cache/staging quotas. Optional native helpers remain isolated capabilities, with explicit unavailable/paused states and live navigation preserved; whisper.cpp/piper run as subprocesses, not linked. Desktop builds do not establish gomobile compatibility or low-resource RSS limits. |
| R2 | **Third-party code licensing** — a contribution carrying code under an incompatible license | all | Contributions are original work under MIT; no code is copied from other projects ([CONTRIBUTING.md](../../CONTRIBUTING.md)). |
| R3 | **OpenAI-compatible dialect drift** (tools/streaming fields differ across vLLM/Ollama/OpenRouter/api-bar.ru) | 0, 2, 3 | Integration tests against a provider matrix in CI. For api-bar.ru specifically, verify streaming, tool-calling, and multimodal endpoints empirically — there is no public documentation. |
| R4 | **App-store policies** (model-weight downloads, background work, sensor access) | 5, 6 | Early guideline review; weights downloaded post-install; `bash` replaced by a safe tool set on mobile; fallback channel — TestFlight/sideload. |
| R5 | **Feature-store tool security** | 7 (design starts in 2) | Permission manifests + sandbox by default + catalog review. External input (MCP tool output, files) is untrusted at the architecture level. |
| R6 | **Scope drag** — 8 phases with one part-time developer | all | Every phase is an independently useful release; phase files keep non-goals explicit; only the active phase is mirrored to GitHub Issues. |
| R7 | **Contract churn in `pkg/agentapi`** after clients exist | 1+ | Contract-first (WP0.1), versioned RPC handshake (WP1.2), golden wire-format tests; semver discipline from Phase 7. |
| R8 | **File-tool confinement has a TOCTOU window** — `tool.Root.Resolve` checks a path (lexically, then through symlinks) before the file is opened or renamed, so a symlink swapped in between escapes the working directory; `bash` is not path-confined at all | 0 (local CLI: accepted), 1+ (core as a service), 7 (third-party tools) | **Done in WP1.7 (2026-10-19):** `tool.Root` opens, stats, writes, renames and walks through `os.Root`, so every path is resolved component by component under the directory at the moment of use; `Resolve` stays as the readable check and for the denied paths. `Root` is the single seam. Keep `bash` behind an explicit confirmation showing the command (WP0.6); revisit both before the core serves more than one user on a host. |
| R9 | **A subscription credential lives on a machine the user controls** — if some models are ever sold by subscription rather than paid per token by the user, the client carries a credential that cannot be hidden: the source is public, the binary is rebuildable, and no attestation root exists on desktop or Raspberry Pi | 7 (design must not be foreclosed earlier) | Do not protect the credential — narrow what it unlocks. Gateway holds the provider keys; the subscription endpoint is task-shaped (an advisor call), not an OpenAI-compatible passthrough; tokens are short-lived and sender-constrained (DPoP/mTLS) so a copied token is inert; the user's own key stays a complete path to every feature. Full design and rejected alternatives in [`subscription-access.md`](subscription-access.md). |
| R10 | **MCP tool schemas consume prompt context**, especially on 32k local models: the Q6 probe measured 9,981 tokens (44.6 KiB) for ten servers, 35% of a 32k window once built-ins are included | 2, 5+ | Default MCP schema budget 48 KiB and per-server 20 KiB; hide whole servers with a warning and show them in `hint mcp status`; per-server `tools:` allow/deny lists; full lazy disclosure in WP2.8. Measurements and policy in [`mcp-client-spike.md`](mcp-client-spike.md#context-budget). |
| R11 | **MCP tool schema numbers can change through the SDK decode**: `inputSchema` arrives as `any`, so numbers become `float64` and integers at or above 2^53 in magnitude or high-precision decimals may be rounded on re-encode | 2 | WP2.1 rejects tools with `abs(v) >= 2^53`, documents the decimal limitation, and keeps a raw `tools/list` path as the fallback. `agentapi.ToolSchema` no longer promises byte-identical passthrough. |
| R12 | **Terminal image protocols are terminal-specific and can corrupt the screen** — kitty placeholders, iTerm2 OSC 1337 and sixel differ in how they reserve cells, scroll and survive a repaint; a wrong guess paints tofu or eats the transcript | 3 | Detect from the client's environment only, keep half-blocks as the always-available fallback, let `display.inline_images` pin the protocol, send the kitty transmit once per image id, and test placeholder cell geometry and the non-TTY path. No DA1 query that can hang a pipe. |
| R13 | **Attachments enlarge sessions and carry sensitive data** — a multi-megabyte image on every JSONL line slows `session.list`, and a document is untrusted text that can prompt-inject or hold a secret | 3 | Store bytes content-addressed outside the JSONL and keep a reference in the message; cap bytes, pixels and count with explicit truncation; label documents as data rather than instructions; refuse protected files; keep bytes and URL query strings out of debug logs. |
| R14 | **The post-v0.4 review becomes an open-ended rewrite or analysis paralysis** | 2R | Timebox it to 2–3 weeks, keep one decision record, ship only high-severity fixes in `v0.4.1`, and turn every other finding into a scored roadmap item. A finding without evidence or a disposition is not closed. |
| R15 | **The adaptive tuning effect becomes hidden profiling or a self-reinforcing loop** | 2R (design), later implementation | Local-only, inspectable, scoped and opt-in; evidence, confidence and decay; explicit beats inferred; no learning from model output without a user signal; a prompt budget; delete and export; guardrail metrics including regressions and unwanted personalization. |
| R16 | **Trend research turns into competitor cargo-culting** | 2R | Score every trend against the product principles and the project's constraints; record what will not be copied; require a falsifiable signal for each bet; treat Hermes v0.23 as one data point, not a template. |
